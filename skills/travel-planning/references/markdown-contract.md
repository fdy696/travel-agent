# Travel Plan Markdown Contract

本文件定义完整旅行计划的固定 Markdown 输出协议。

## 1. 核心规则

完整旅行计划的核心标题属于稳定 Contract：

- 标题名称不得修改
- 不得用同义标题替代
- 不得添加 Emoji
- 不得改变标题层级
- 不得把两个核心模块合并

内容可以灵活，核心结构必须稳定。

## 2. 标准结构

```markdown
# {目的地}{天数}旅行计划

## 行程概览

- 日期 / 天数：
- 旅行者：
- 旅行风格：
- 核心路线：
- 预算定位：

## 行前准备

- 大交通：
- 天气：
- 住宿区域：
- 当地交通：
- 预约事项：
- 必备物品：

## Day 1｜{主题 / 区域}

### 上午

...

### 下午

...

### 晚上

...

### 交通

...

### 费用

...

### 提醒

...

## Day 2｜{主题 / 区域}

...

## 住宿建议

...

## 美食建议

...

## 预算参考

...

## 出行提醒

...
```

## 3. 固定标题

必须使用：

```markdown
## 行程概览
## 行前准备
## 住宿建议
## 美食建议
## 预算参考
## 出行提醒
```

不得使用同义标题替代

例如：

```markdown
## 📌 行前准备
```

不能替代：

```markdown
## 行前准备
```

例如：

```markdown
## 整体安排
```

不能替代：

```markdown
## 行程概览
```

## 4. 行程概览固定字段

```markdown
- 日期 / 天数：
- 旅行者：
- 旅行风格：
- 核心路线：
- 预算定位：
```

信息未知时可以写“未特别限制”、合理概括或必要假设，但不得编造用户个人信息。

## 5. 每日标题

每一天必须使用：

```markdown
## Day N｜主题 / 区域
```

例如：

```markdown
## Day 1｜龙门石窟 · 洛阳博物馆
## Day 2｜老城文化线
## Day 3｜白马寺 · 返程
```

普通行程优先使用：

```markdown
### 上午
### 下午
### 晚上
```

根据真实情况也允许 `### 清晨`、`### 全天`、`### 夜间`。

每个完整 Day 应包含：

```markdown
### 交通
### 费用
### 提醒
```

## 6. 模块职责

### 行前准备

写出发前需要知道和准备的内容，如大交通、天气 / 气候、住宿区域、当地交通、预约、证件、衣物、防晒雨具等。

### 住宿建议

优先推荐区域、商圈、地铁站附近及选择理由；没有可靠依据时，不编造具体酒店。

### 美食建议

推荐当地代表美食、用餐区域和与每日路线结合的餐饮建议；没有可靠依据时，不编造具体餐厅事实。

### 预算参考

按大交通、住宿、当地交通、门票、餐饮、体验等估算；若用户有明确预算，应说明方案是否大致符合。

### 出行提醒

写整趟旅行过程中持续需要注意的预约、天气变化、证件、支付、行李、客流、景区规则、安全等事项，不要与行前准备大量重复。

## 7. 特殊旅行类型

允许增加额外模块，例如：

```markdown
## 自驾路线建议
## 雪场与装备
## 登船与岸上观光
## 亲子注意事项
```

额外模块只能补充，不能替代核心模块。

## 8. 输出前检查

发送完整计划前确认至少存在：

```text
# {目的地}{天数}旅行计划
## 行程概览
## 行前准备
## Day 1｜...
## 住宿建议
## 美食建议
## 预算参考
## 出行提醒
```

多日旅行的 Day 数量必须与旅行天数一致。

Markdown Contract 的稳定性属于完整旅行计划正确性的一部分。
