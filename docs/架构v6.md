# 行伴 Travel Agent v6 架构

## 1. 目标

行伴是一个面向 C 端用户的通用旅行 Agent。

当前阶段优先完成：

- 自然语言旅行问答
- 实时旅行信息查询
- 完整多日旅行计划
- 同会话自然语言修改计划
- 复杂 Research 的上下文隔离

当前旅行计划继续使用 Markdown 作为用户可见表示，不引入 Plan DB、CRUD、Renderer 或固定 Planning Workflow。

## 2. 核心原则

> 模糊、概率性的语义决策交给模型；确定性的能力和边界交给代码。

进一步：

```text
Main Agent
→ 意图理解、Tool / Skill / delegation 判断、最终规划、最终回答

Skill
→ 旅行规划方法与 Markdown Contract

Tool
→ 搜索、天气、地图等确定性外部能力

Built-in general-purpose SubAgent
→ 复杂、高噪声、多步骤 Research 的 Context Isolation

Checkpointer
→ 同 thread 连续对话
```

不因为任务逻辑上存在“需求 → Research → Plan → Output”就把它写成固定 Graph。

## 3. 总体架构

```text
                         User
                           │
                           ▼
                    Main Deep Agent
                           │
          ┌────────────────┼────────────────┐
          │                │                │
          ▼                ▼                ▼
 Travel Planning Skill   Travel Tools      task
                          │                │
                    search/weather         ▼
                    maps              general-purpose
                                           │
                                  isolated context
                                           │
                              search / weather / maps
                                           │
                                           ▼
                                  Research Findings
                                           │
                    ┌──────────────────────┘
                    ▼
                 Main Agent
                    │
                    ▼
          Final Markdown Plan / Answer
                    │
                    ▼
                   User
```

Main Agent 始终是唯一用户入口和最终回答者。

## 4. Research 路由

### 简单事实

Main 直接回答或调用一个 Tool。

例如：

```text
东京明天天气怎么样？
→ get_weather
```

### 普通旅行 Research

Main 直接组合少量 Tools。

例如：

```text
洛阳三日游
→ Skill
→ search / maps / weather（按需）
→ Main Final Plan
```

### 复杂、高噪声 Research

Main 使用 Deep Agents 默认 `task` Tool 委派：

```text
task(
  subagent_type="general-purpose",
  description="完整 Research Brief"
)
```

适合：

- 多城市复杂交通比较
- 多个 Pass / 票制比较
- 多来源规则核验
- 多套路线候选研究
- 预计需要连续多次 Tool Call 的独立 Research

SubAgent 只返回 Findings，不负责 Final Plan。

## 5. 为什么不自定义 Researcher

当前 `deepagents==0.7.4` 会在未提供同名 SubAgent 时自动加入 `general-purpose`，并暴露 `task` Tool。

它已经具备：

- 与 Main 相同的业务 Tools
- 独立 context window
- Filesystem middleware
- Summarization middleware
- Main Skills（当前 default general-purpose 会继承）

因此如果自定义 Travel Researcher 仍只是“多搜几次然后总结”，会和框架默认能力重复。

当前选择：

```text
❌ custom Travel Researcher
❌ deep_research Agent
✅ Deep Agents general-purpose
```

以后只有在需要独立模型、独立 Tools、独立 Research 方法论或固定 structured findings 时，再考虑业务专用 SubAgent。

## 6. Delegation Contract

Main 调用 `task` 时必须写完整 Research Brief，至少提供：

1. 当前旅行背景
2. 研究目标
3. 用户相关约束
4. 需要核验 / 比较的问题
5. 期望结果：关键事实、比较结果、推荐倾向、冲突 / 不确定性、重要来源
6. 明确说明不要生成最终旅行计划

原因：同步 SubAgent 是 stateless invocation，不直接读取 Main 的完整 conversation messages。

## 7. Skill

```text
skills/
└── travel-planning/
    ├── SKILL.md
    └── references/
        └── markdown-contract.md
```

`SKILL.md`：

- 需求理解
- Research 判断
- selective delegation
- 路线和节奏设计
- 预算
- 修改语义
- 最终质量检查

`references/markdown-contract.md`：

- 固定 Markdown 标题
- Day 结构
- 行程概览字段
- 住宿 / 美食 / 预算 / 出行提醒结构

只有生成或修改完整计划时读取 Markdown Contract。

## 8. Context Engineering

Deep Agents 默认承担两类底层 Context 管理：

```text
大 Tool Result
→ Filesystem offload

长 Conversation
→ Summarization
```

`general-purpose` 解决另一类问题：

```text
大量中间 Research Tool Calls
→ isolated context
→ Main 只接收最终 Findings
```

因此：

> Offloading 控制单条数据有多大；SubAgent 控制谁需要看到这些中间数据。

## 9. CLI 开发调试

CLI 是开发入口，因此默认开启详细调试模式。

```bash
travel-agent
```

默认展示：

- Main 节点执行
- SubAgent namespace
- Skill / filesystem Tool 调用
- Travel Tool 调用参数
- 完整 Tool Result
- `task -> general-purpose` 委派参数
- AIMessage 元数据 / token usage（provider 返回时）
- non-message state updates
- LangGraph runtime debug payload
- 异常 traceback
- 每轮执行耗时
- 最终 Main 回答

底层使用：

```python
agent.astream(
    ...,
    stream_mode=["updates", "debug"],
    subgraphs=True,
    version="v2",
)
```

需要只查看最终答案时：

```bash
travel-agent --no-debug
```

CLI 不尝试展示模型隐藏 chain-of-thought，只展示框架真正暴露的 execution events。

## 11. 当前最终架构

```text
Main Agent
├── Travel Planning Skill
├── Travel Tools
├── Deep Agents built-in general-purpose
├── Filesystem / Context Offload
├── Summarization
└── Checkpointer
```

Agent 数量不按照业务能力数量拆分，而按照是否真正需要独立认知上下文拆分。
