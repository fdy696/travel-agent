# 行伴 Travel Agent v6 架构

## 1. 目标

行伴是面向 C 端用户的通用旅行 Agent。

当前阶段优先完成：

- 自然语言旅行问答
- 实时旅行信息查询
- 完整多日旅行计划
- 同会话自然语言修改计划
- 多主题 Research 上下文隔离
- 确定性预算计算与币种换算
- CLI 可观测调试

当前旅行计划继续使用 Markdown 作为用户可见表示，不引入 Plan DB、CRUD、Renderer、固定 Planning Workflow 或 FastAPI 接口。

## 2. 核心原则

> 模糊、概率性的语义决策交给模型；确定性的能力和边界交给代码。

对应职责：

```text
Main Agent
→ 用户交互、需求澄清、最终方案选择、最终规划、最终回答

Travel Planning Skill
→ 旅行规划方法与 Markdown Contract

Travel Researcher
→ 多主题外部事实 Research，隔离中间 Tool Context，只返回 Findings

Research Tools
→ search / weather / maps

Deterministic Tools
→ calculate_budget / convert_currency

Checkpointer
→ 同 thread 连续对话
```

Agent 数量按“是否需要独立认知上下文”拆分，不按业务功能数量拆分。

## 3. 完整旅行规划链路

```text
User
 ↓
Main
 ↓
必要需求澄清
 ↓
travel-planning Skill
 ↓
task(subagent_type="travel-researcher")
 ↓
Researcher: search / weather / maps
 ↓
Research Findings
 ↓
Main 选定最终路线 / 交通 / 住宿 / 活动
 ↓
calculate_budget（按需）
 ↓
convert_currency（按需）
 ↓
Markdown Contract
 ↓
Main Final Markdown Plan
```

这是一条职责约束，不是固定 LangGraph Workflow。

## 4. Main Agent

Main 是唯一用户入口和最终语义负责人。

负责：

- 判断当前请求是闲聊、普通旅行问答还是完整旅行规划
- 在完整规划 Research 前澄清会改变整体方案的关键条件
- 对不影响整体方案的非关键偏好做合理假设
- 不在 Research 前把 JR Pass、城市 Pass 等经济性方案设成默认结论
- 根据 Research Findings 做最终路线、节奏、预算和取舍
- 将最终采用方案交给预算计算器
- 需要人民币等辅助参考时调用汇率换算
- 最终按照 Markdown Contract 输出完整计划

## 5. Travel Researcher

`travel-researcher` 是完整规划唯一的 Research Workspace。

只负责：

- 当前交通 / 路线 / 耗时
- 开放 / 预约 / 门票 / Pass
- 当前运营规则
- 与旅行日期相关的天气 / 季节事实
- 其他会影响计划可执行性的外部事实

Researcher 只持有：

```text
search_travel_info
search_maps
get_weather
```

Researcher 不读取 Travel Planning Skill，不读取 Markdown Contract，不生成最终 Day-by-Day Plan。

Deep Agents 内置 `general-purpose` 已通过 HarnessProfile 禁用，业务只保留显式注册的 `travel-researcher`。

## 6. Budget Calculator

`calculate_budget` 是纯确定性计算能力。

它：

- 不保存任何城市价格
- 不搜索价格
- 不判断旅行方案
- 只接收 Main 已经选定的最终方案项目
- 支持区间、数量、人数、分类汇总、总额和人均

因此：

```text
价格事实 → Researcher
最终采用什么 → Main
加总是否正确 → calculate_budget
```

未采用的备选交通 / Pass / 酒店价格不得混入最终预算。

## 7. Currency Converter

事实价格始终保留当地货币。

`convert_currency` 只做辅助换算：

```text
当地事实价格（例如 JPY）
 ↓
Frankfurter current reference rate
 ↓
辅助参考币种（例如 CNY）
```

规则：

- 不使用裸 `¥` 表示日元
- 同一预算模块的多个金额使用同一条参考汇率
- 汇率失败时只输出当地货币，不猜汇率
- `APP_ENV=test` 使用离线 Fake rate，仅用于确定性测试

## 8. Model Provider

模型供应商和运行环境相互独立：

```text
LLM_PROVIDER
├── deepseek
└── ollama

APP_ENV
├── development
├── test
└── production
```

例如本地开发仍可使用 DeepSeek：

```env
APP_ENV=development
LLM_PROVIDER=deepseek
```

也可以本地使用 Ollama：

```env
APP_ENV=development
LLM_PROVIDER=ollama
```

Main 和 Travel Researcher 当前使用同一个已构造模型实例。

## 9. Search Provider

```text
APP_ENV=development
→ DDGS 免费搜索，不调用 Tavily

APP_ENV=test
→ FakeSearch，完全离线

APP_ENV=production
→ Tavily primary → DDGS fallback
```

Agent 只看到统一的 `search_travel_info`，不负责选择搜索供应商。

## 10. CLI 调试

当前阶段继续以 CLI 为唯一开发入口：

```bash
uv run python cli.py
```

CLI 启动时展示：

- APP_ENV
- 当前 Model Provider / model
- Search Provider
- FX Provider

Debug 模式展示 Main / SubAgent / Tool / Skill / Contract 等执行轨迹，完整 raw events 写入日志。

## 11. 当前明确不做

```text
❌ FastAPI / Web API
❌ Planning Workflow
❌ Python Intent Router
❌ Planner Agent
❌ Writer Agent
❌ Validator Agent
❌ Budget Agent
❌ Currency Agent
❌ Plan DB / CRUD
```


## 9. Execution Guard

单次 Agent 执行通过 LangGraph `recursion_limit` 设置代码级硬上限。
默认 `AGENT_RECURSION_LIMIT=80`，用于截断 Main / SubAgent 的异常循环；它限制的是 graph super-steps，不等同于模型调用次数或 Tool Call 次数。
正常停止仍由 Agent 语义判断负责，Execution Guard 只作为最后保险。

达到上限时 CLI 捕获 `GraphRecursionError`，终止本轮并提示查看详细日志。
